# SugamFlow फ़ील्ड फ़ोर्स — प्रवाह और सेल्समैन/प्रमोटर डैशबोर्ड गाइड (हिंदी)

यह दस्तावेज़ **लीड → कन्वर्ज़न** प्रक्रिया, **फ़ील्ड फ़ोर्स वर्कस्पेस** डैशबोर्ड के अपडेट के बाद उपयोग, और पुराने “नकली दुकान पंजीकरण” प्रवाह से अंतर समझाता है।

तकनीकी विवरण: [FIELDFORCE-LEAD-ARCHITECTURE.md](./FIELDFORCE-LEAD-ARCHITECTURE.md)  
अंग्रेज़ी संस्करण: [FIELDFORCE-SALESMAN-PROMOTER-GUIDE.md](./FIELDFORCE-SALESMAN-PROMOTER-GUIDE.md)

**PDF बनाने के लिए:** `docs` फ़ोल्डर में `npm run pdf:fieldforce` चलाएँ।

**दैनिक कार्य + DB टेबल/मान:** [FIELDFORCE-DAILY-WORK-AND-DATA-REFERENCE-Hindi.md](../sugamflow-docs/docs/FIELDFORCE-DAILY-WORK-AND-DATA-REFERENCE-Hindi.md)

## 1. कौन क्या उपयोग करता है

| भूमिका | लॉगिन भूमिका (JWT) | लैंडिंग पेज | मुख्य काम |
|--------|-------------------|-------------|-----------|
| **बिज़नेस प्रमोटर** | `FIELD_FORCE_PROMOTER` | `/field-force/workspace` | क्षेत्र; लीड बनाना; रूपांतरण |
| **सेल्समैन** | `FIELD_FORCE_SALESMAN` | `/field-force/workspace` | प्रमोटर के अंतर्गत; स्वयं को असाइन लीड |
| **सुपर एडमिन** | `SUPER_ADMIN` | प्लेटफ़ॉर्म / फ़ील्ड फ़ोर्स एडमिन | प्रमोटर, सेल्समैन, कमीशन योजना |

प्रमोटर/सेल्समैन खाते में लॉगिन पर **`promoterId`** या **`salesmanId`** होना ज़रूरी है। इसके बिना वर्कस्पेस त्रुटि दिखाता है और लीड असाइन नहीं हो सकती।

## 2. पुराना बनाम नया प्रवाह (डैशबोर्ड क्यों बदला)

### पहले (बंद — उपयोग न करें)

```
फ़ील्ड विज़िट → "बाहरी दुकान ID" + नाम दर्ज
              → shop_registrations में सेव (असली दुकान जैसा दिखता था)
              → रिपोर्ट और ग्राहक DB प्रदूषित
```

### अब (वर्तमान)

```
फ़ील्ड विज़िट → व्यापारिक लीड (केवल संभावित ग्राहक)
              → गतिविधि लॉग (विज़िट, डेमो, फ़ॉलो-अप)
              → कन्वर्ज़न (KYC → सब्सक्रिप्शन → पूर्ण)
              → shop-service में असली दुकान + मालिक को ईमेल आमंत्रण
```

| विषय | पुराना | नया |
|------|--------|-----|
| संभावित ग्राहक | `shop_registrations` | `business_leads` |
| असली दुकान | पंजीकरण पर (गलत) | केवल **कन्वर्ज़न पूर्ण** पर |
| डुप्लिकेट जाँच | कमज़ोर | मोबाइल / GST / नाम / GPS |
| कमीशन | दुकान अनुमोदन | लीड, डेमो, कन्वर्ज़न |
| UI | “नई दुकान पंजीकरण” | “नई व्यापारिक लीड” |

**नए संभावित ग्राहकों के लिए shop registration API का उपयोग न करें।**

## 3. अंत-से-अंत व्यापारिक प्रवाह

प्रवाह चित्र: `docs/diagrams/04-fieldforce-lead-flow.png`

### लीड स्थिति (पाइपलाइन)

| स्थिति | अर्थ |
|--------|------|
| `NEW` | अभी बनी |
| `CONTACTED` | कॉल/विज़िट लॉग |
| `INTERESTED` | रुचि बढ़ रही |
| `DEMO_GIVEN` | डेमो दर्ज |
| `FOLLOWUP` | फ़ॉलो-अप |
| `NEGOTIATION` | सब्सक्रिप्शन चरण |
| `CONVERTED` | दुकान बन गई — जीत |
| `REJECTED` | हार |
| `DUPLICATE` | डुप्लिकेट |

कुछ गतिविधियों पर स्थिति अपने आप बदल सकती है (जैसे `DEMO` → `DEMO_GIVEN`).

### कन्वर्ज़न चरण

| चरण | कब |
|------|-----|
| `VERIFICATION` | कन्वर्ज़न शुरू |
| `KYC` | KYC सत्यापित |
| `SUBSCRIPTION_SELECTION` | योजना सेव |
| `MERCHANT_CREATION` / `SHOP_CREATION` | पूर्ण करते समय |
| `COMPLETED` | दुकान + आमंत्रण सफल |
| `FAILED` | shop-service या ईमेल त्रुटि |

## 4. सेल्समैन / प्रमोटर डैशबोर्ड

**URL:** `/field-force/workspace`

### 4.1 ऊपर के सारांश कार्ड

| कार्ड | अर्थ |
|--------|------|
| **Leads / लीड** | सक्रिय व्यापारिक लीड |
| **Converted / रूपांतरित** | `CONVERTED` स्थिति |
| **Activities / गतिविधियाँ** | इस महीने की फ़ील्ड गतिविधियाँ |
| **Legacy shop regs** | पुराने पंजीकरण (इतिहास) |

### 4.2 बाएँ — बनाएँ और सूची

1. **नई व्यापारिक लीड** — व्यापार का नाम, मोबाइल (अनिवार्य), मालिक, शहर, राज्य
2. **मेरी लीड** — भूमिका अनुसार फ़िल्टर:
   - **सेल्समैन:** `assignedSalesmanId` = आपकी ID
   - **प्रमोटर:** `createdByPromoterId` = आपकी ID

### 4.3 दाएँ — चुनी हुई लीड

| खंड | क्रियाएँ |
|------|---------|
| **लीड शीर्षक** | कोड `LD-123`, स्थिति, दुकान ID यदि रूपांतरित |
| **गतिविधि लॉग** | प्रकार, नोट्स, अगली फ़ॉलो-अप तिथि |
| **इतिहास** | कालानुक्रमिक सूची |
| **कन्वर्ज़न** | सब्सक्रिप्शन, KYC, मालिक ईमेल/यूज़रनेम, **पूर्ण कन्वर्ज़न** |

## 5. दैनिक उपयोग — चरण दर चरण

### चरण 1 — लॉगिन

1. `FIELD_FORCE_SALESMAN` या `FIELD_FORCE_PROMOTER` से लॉगिन।
2. सीधे **फ़ील्ड फ़ोर्स वर्कस्पेस** खुलेगा (POS नहीं).

### चरण 2 — संभावित ग्राहक (लीड)

1. **व्यापार का नाम** और **मोबाइल** भरें।
2. **Save lead / लीड सेव** दबाएँ।
3. डुप्लिकेट हो तो त्रुटि — अलग रिकॉर्ड या ऑफ़लाइन सुलझाएँ।
4. **मेरी लीड** में `NEW` और `LD-{id}` दिखेगी।

### चरण 3 — लीड पर काम

1. सूची में लीड क्लिक करें।
2. गतिविधि: `VISIT`, `CALL`, `DEMO`, `FOLLOWUP` आदि।
3. नोट्स और **अगली फ़ॉलो-अप** तिथि।
4. **Log activity** दबाएँ।

### चरण 4 — असली ग्राहक में बदलें

1. **Conversion pipeline** खोलें।
2. **सब्सक्रिप्शन योजना** (`MONTHLY`, `YEARLY`).
3. **KYC verified** चेक या **Mark KYC**.
4. **Save subscription**.
5. **मालिक यूज़रनेम** और **ईमेल** (पासवर्ड सेटअप लिंक जाएगा).
6. **Complete conversion**.

**सफलता पर:**

- स्थिति → `CONVERTED`
- दुकान ID जैसे `FF-LD-42`
- मालिक आमंत्रण ईमेल की स्थिति संदेश में
- कमीशन योजना अनुसार `CONVERSION` इवेंट

नई दुकान `PENDING` रहती है जब तक सुपर एडमिन सक्रिय न करे।

### चरण 5 — रिफ़्रेश

**Refresh** से कार्ड और सूची दोबारा लोड।

## 6. प्रमोटर बनाम सेल्समैन

| क्षमता | प्रमोटर | सेल्समैन |
|--------|---------|----------|
| लीड देखना | स्वयं द्वारा बनाई (`createdByPromoterId`) | स्वयं को असाइन (`assignedSalesmanId`) |
| लीड बनाना | हाँ | हाँ |
| गतिविधि लॉग | हाँ | हाँ |
| कन्वर्ज़न पूर्ण | हाँ | हाँ |
| दूसरे की लीड वर्कस्पेस में | नहीं | नहीं |

## 7. सुपर एडमिन

**स्क्रीन:** Super Admin → Field Force

- प्रमोटर और क्षेत्र  
- सेल्समैन  
- कमीशन योजना और प्रविष्टियाँ  
- पुराने shop registrations (केवल इतिहास)

रूपांतरित दुकानें: रजिस्ट्री में `PENDING` → सक्रिय करें।

## 9. समस्या निवारण

| लक्षण | संभावित कारण |
|--------|----------------|
| promoter/salesman id गायब | auth खाता लिंक नहीं |
| डुप्लिकेट लीड | समान मोबाइल / GPS / नाम |
| खाली डैशबोर्ड | fieldforce-service या गेटवे |
| कन्वर्ज़न विफल | shop-service बंद या इंटीग्रेशन बंद |
| ईमेल नहीं | auth-service कॉन्फ़िग |
| खाली सूची | गलत भूमिका फ़िल्टर |
